% Abstract
% ------------------------------------------------------------
\begin{abstract}
Smartphone images captured through dirty lenses exhibit diverse degradations, including dust, fingerprints, water droplets, scratches, and mixed artifacts.
The SIDL benchmark studies this real-world restoration problem under fixed-model inference, where the same restoration model is applied to all inputs.
This work asks a complementary question: \emph{does every dirty-lens image require the same restoration budget?}
We propose \textbf{FastGainRouter}, a lightweight input-adaptive framework that chooses among three branches: \textit{Input} for bypassing restoration, \textit{Tiny} for low-cost restoration, and \textit{Base} for stronger restoration.
Rather than predicting unstable hard oracle labels, the router predicts restoration gains of Tiny over Input and Base over Tiny.
On SIDL validation, the proposed router provides favorable PSNR-latency operating points: a balanced mode slightly improves PSNR over Always Base while reducing latency, and an efficient mode yields larger latency reduction with only a small PSNR loss.
These results suggest that adaptive restoration budget selection is a useful complement to fixed-model dirty-lens restoration.
\end{abstract}

\textbf{Keywords:} dirty-lens restoration, SIDL, dynamic inference, efficient image restoration, routing.

% 1. Introduction
% ------------------------------------------------------------
\section{Introduction}

Smartphone cameras are widely used in daily life, but their image quality can be degraded by contaminants on the lens surface.
Water droplets, dust, fingerprints, scratches, and mixed contaminants can introduce spatially non-uniform blur, light scattering, local occlusion, contrast reduction, and color distortion.
These artifacts differ from standard synthetic degradations such as Gaussian noise or motion blur because the degradation is introduced before image formation and varies across spatial regions and scenes.

The SIDL benchmark introduced a real-world dataset for restoring smartphone images captured through dirty lenses \cite{sidl2025}.
It provides paired degraded and clean reference images and evaluates representative restoration models under a fixed-model setting.
Its Easy, Medium, and Hard categories are used for evaluation and analysis, not as routing signals for selecting different restoration models.
Thus, the benchmark primarily asks how well a given restoration model performs on dirty-lens images.

We study a complementary direction: \textit{input-adaptive restoration budget selection}.
In dirty-lens restoration, not all inputs require the same computation.
Some images are already close to the reference and can be damaged by unnecessary restoration.
Many images can be restored sufficiently by a small model.
Only a subset requires a stronger model.
This motivates a routing framework that decides whether to skip restoration, use a lightweight branch, or use a stronger branch for each input.

We introduce \textbf{FastGainRouter}, which selects among three branches:
\textbf{Input}, which returns the degraded image unchanged;
\textbf{Tiny}, a width-4 NAFNet-based restoration model;
and \textbf{Base}, a width-8 NAFNet-based model.
Instead of directly classifying the best branch, FastGainRouter predicts two gains: the expected improvement of Tiny over Input and the additional improvement of Base over Tiny.
This gain-based formulation avoids treating very small metric differences as hard class boundaries and better matches the quality-efficiency trade-off.

\newpage
Our contributions are:
\begin{itemize}
    \item We identify that over-restoration occurs in SIDL: Input, Tiny, and Base are each optimal for a non-trivial subset of validation samples.
    \item We formulate adaptive restoration as gain prediction rather than hard branch classification, using lightweight image statistics at test time.
    \item We show that FastGainRouter can reduce average component-based latency while maintaining comparable restoration quality to fixed Base inference.
\end{itemize}

\section{Related Work}

\paragraph{Dirty-lens image restoration.}
Image restoration has traditionally focused on denoising, deblurring, super-resolution, deraining, and dehazing.
Dirty-lens restoration differs because contaminants lie in front of the camera lens and create spatially varying scattering and occlusion.
SIDL addresses this problem by collecting paired smartphone images with realistic lens contaminants \cite{sidl2025}.
Our work does not replace the SIDL benchmark; rather, it explores whether restoration computation should be allocated adaptively across inputs.

\paragraph{Deep image restoration.}
Modern restoration backbones include multi-stage CNNs, transformers, and simplified convolutional baselines.
MPRNet uses a multi-stage progressive design \cite{mprnet2021}, Restormer introduces an efficient transformer for high-resolution restoration \cite{restormer2022}, and NAFNet provides a simple activation-free restoration baseline \cite{nafnet2022}.
We use NAFNet variants only to construct controlled restoration branches.
The focus of this work is not a new backbone, but when to invoke each branch.

\paragraph{Dynamic inference.}
Dynamic inference methods allocate computation according to input difficulty.
BranchyNet uses early exits \cite{branchynet2016}, SkipNet learns dynamic layer skipping \cite{skipnet2018}, Slimmable Networks vary network width \cite{slimmable2019}, and Once-for-All trains a super-network for many deployment constraints \cite{onceforall2020}.
Unlike classification-oriented dynamic inference, our router predicts restoration gains for dense image restoration outputs.

\section{Problem Setup and Method}

Given a degraded dirty-lens input image $x$, a fixed restoration pipeline applies one model to all inputs.
We instead define a branch set
\[
\mathcal{A}=\{\text{Input},\text{Tiny},\text{Base}\},
\]
and select a branch $a(x)\in\mathcal{A}$ for each sample.
The Input branch is the identity path, Tiny is a lightweight restoration model, and Base is a stronger restoration model.

\begin{figure}[t]
    \centering
    \includegraphics[width=0.99\textwidth]{method_overview.png}
    \caption{
    Overview of FastGainRouter.
    The router computes lightweight image statistics from the degraded input, predicts restoration gains, and selects Input, Tiny, or Base.
    Ground truth, difficulty labels, and metadata are not used at test time.
    }
    \label{fig:overview}
\end{figure}

\subsection{Branch Design}

The \textbf{Input} branch is included because restoration is not always beneficial.
Some validation samples are closer to the reference before restoration, so forcing them through a restoration model may introduce smoothing, color shifts, or texture changes.

The \textbf{Tiny} branch is a width-4 NAFNet-based model.
It serves as a low-cost restoration path for inputs where a small model is sufficient.
The \textbf{Base} branch is a width-8 NAFNet-based model and is used when stronger restoration is expected to provide additional benefit.

\subsection{Gain-Based Router}

For each training sample, we compute PSNR values for Input, Tiny, and Base:
$P_I$, $P_T$, and $P_B$.
We define the gain targets
\[
g_{T-I}=P_T-P_I,\qquad g_{B-T}=P_B-P_T.
\]
The first gain measures whether Tiny improves over bypassing restoration.
The second measures whether Base provides enough additional benefit over Tiny.

FastGainRouter is implemented as a random-forest regressor using nine lightweight input statistics: grayscale mean and standard deviation, dark and bright pixel ratios, saturation mean and standard deviation, HSV value mean and standard deviation, and Laplacian variance.
Given predicted gains $\hat{g}_{T-I}$ and $\hat{g}_{B-T}$, the router selects
\[
a(x)=
\begin{cases}
\text{Input}, & \hat{g}_{T-I}<\tau_{\text{restore}},\\
\text{Base}, & \hat{g}_{B-T}>\tau_{\text{base}},\\
\text{Tiny}, & \text{otherwise}.
\end{cases}
\]
The thresholds are selected on an inner validation split.

\section{Experiments}

\subsection{Dataset and Splits}

We use the official SIDL train and validation splits.
The official validation set is held out for final evaluation only.
Since SIDL does not provide a separate development split for our routing policy, we construct two internal splits from the official training set: an inner training split (\textit{train\_inner}) and an inner validation split (\textit{es\_val\_inner}).
These names are specific to this project and are used to distinguish our internal protocol from the official SIDL split.

The \textit{train\_inner} split is the source of all trainable components in the final pipeline.
It is used to train the Tiny and Base restoration branches.
After the restoration branches are fixed, the same split is also used to generate router supervision: we run Input, Tiny, and Base on each train\_inner sample and compute the Tiny-over-Input and Base-over-Tiny gains against the reference.
Thus, train\_inner defines the data from which the router learns how the trained restoration branches behave.

The \textit{es\_val\_inner} split is not used for gradient updates of the restoration branches or the router.
It is used for model selection and policy calibration: Tiny checkpoint selection, early stopping, and threshold selection for FastGainRouter.
This split is therefore a development set inside the official training data, not an additional training set.

The official validation split is used only once the restoration branches, router, and routing thresholds have been fixed.
No image from the official validation split is used for branch training, router training, early stopping, or threshold tuning.
This protocol allows us to report final results on a held-out validation set while still tuning the model within the official training data.

All internal splits are constructed at the case level rather than at the patch level.
SIDL contains multiple image patches that can originate from the same scene case.
If patches from the same case were split across train and validation subsets, the validation results could be inflated by scene-level leakage.
The case-level split reduces this risk by ensuring that all patches from the same case are assigned to the same internal split.

\subsection{Operating Points}

FastGainRouter uses threshold-based routing, so different thresholds produce different quality-latency operating points.
We report two representative settings selected on the inner validation split.
The \textbf{Balanced} setting uses thresholds that prioritize restoration quality while still reducing average latency relative to Always Base.
The \textbf{Efficient} setting uses a more aggressive policy that reduces Base usage further and allows a small PSNR drop for larger latency reduction.
These names are fixed before the final official validation evaluation and correspond to two points on the same routing trade-off curve, not to separately trained restoration models.

\subsection{Implementation and Latency Protocol}

Tiny and Base are NAFNet variants with widths 4 and 8, respectively.
Tiny candidates with learning rates $1\times10^{-3}$ and $5\times10^{-4}$ are compared on the inner validation split, and the $1\times10^{-3}$ model is used.
After training Tiny and Base, we run them on train\_inner to generate gain targets for the router.
Router thresholds are selected on es\_val\_inner.

We report PSNR, SSIM, LPIPS, and latency.
For dynamic routing, latency is a measured component-based pipeline estimate:
\[
L=L_{\text{feature}}+L_{\text{router}}+L_{\text{branch}}.
\]
This is not a fully optimized deployment runtime; it is intended to compare average computation under a batch/offline restoration setting.
For fixed baselines, the latency corresponds to the measured validation pipeline latency of the selected branch under the same evaluation procedure.
For FastGainRouter, the reported latency includes fast feature extraction, batch router prediction, and the inference time of the branch selected for each sample.

\section{Results}

\subsection{Main Quantitative Comparison}

The main comparison evaluates whether adaptive routing can improve the PSNR-latency trade-off over fixed-branch inference.
Always Base is the strongest fixed-branch baseline in terms of PSNR, SSIM, and LPIPS among the three main branches, so it serves as the primary reference point.
Always Tiny represents a lower-cost restoration baseline, while Always Input serves as a no-restoration lower bound.

Ours-Balanced achieves a near-Base operating point with lower latency.
It improves PSNR over Always Base by 0.031 dB while reducing latency by 9.1\%.
This gain is small in absolute PSNR, but it is meaningful for the goal of this work because the stronger fixed branch is not invoked for every input.

Ours-Efficient shifts the policy toward lower computation.
Compared with Always Base, it reduces latency by 18.5\% with a 0.066 dB PSNR drop.
Compared with Always Tiny, it improves PSNR by 0.040 dB while reducing latency by 2.1\%.
Thus, the efficient setting is not merely a lower-cost variant of Base; it also provides a better PSNR-latency point than always using Tiny.

The improvement should be interpreted specifically as a PSNR-latency trade-off.
Ours-Balanced does not uniformly dominate Always Base across SSIM and LPIPS, and Ours-Efficient slightly worsens LPIPS compared with Always Tiny.
For this reason, we use PSNR-latency as the main quantitative claim and discuss the remaining metric trade-offs later.

\subsection{Operating Points and Branch Usage}

The two FastGainRouter settings correspond to different calibrated operating points of the same gain-based router.
In the balanced setting, $(\tau_{\mathrm{restore}}, \tau_{\mathrm{base}})=(0.3,0.1)$, which makes the policy more willing to apply restoration and to invoke Base.
This setting selects Base for 49.3\% of validation samples and therefore preserves near-Base restoration quality while reducing average latency.

The efficient setting uses larger thresholds, $(\tau_{\mathrm{restore}}, \tau_{\mathrm{base}})=(0.6,0.5)$.
This makes the router more conservative about restoration and more selective about Base selection.
As a result, Base usage decreases from 49.3\% to 13.2\%, while Tiny usage increases from 39.6\% to 71.7\%.
This shift in branch usage explains why Ours-Efficient achieves a larger latency reduction with only a small PSNR loss.

Figure~\ref{fig:tradeoff-action} visualizes the resulting PSNR-latency behavior and branch usage.
Ours-Balanced moves from Always Base toward lower latency while slightly improving PSNR, whereas Ours-Efficient moves from Always Tiny toward higher PSNR while also reducing latency slightly.
The branch-usage plot shows that the efficient setting mainly reduces computation by replacing many Base decisions with Tiny decisions, rather than by simply bypassing restoration.
Since the PSNR axis is zoomed, the visual trends should be interpreted together with the numerical values in Table~\ref{tab:main}.

\subsection{Branch Diversity and Gain Analysis}

Adaptive routing is useful only if different inputs prefer different restoration budgets.
The branch-level statistics in Table~\ref{tab:branch-gain} support this condition.
Under PSNR, Input, Tiny, and Base are optimal for 27.0\%, 27.8\%, and 45.2\% of validation samples, respectively.
This indicates that no single branch is optimal for all inputs, and that fixed-model restoration can be inefficient or unnecessary for a non-trivial subset of samples.

The gain statistics show why selective use of Base is reasonable.
Tiny improves over Input by 1.315 dB on average, and 70.3\% of samples gain more than 0.2 dB from Tiny restoration.
In contrast, Base improves over Tiny by only 0.106 dB on average, with a median gain of 0.061 dB.
Thus, Tiny provides most of the restoration benefit for many inputs, while Base is useful mainly for the subset where the additional gain justifies its cost.

\section{Discussion and Conclusion}

FastGainRouter demonstrates that adaptive restoration budget selection can be useful on SIDL, but the results should be interpreted within the scope of this study.
The method is designed as a feasibility study for input-adaptive computation allocation, not as a fully optimized deployment system or a replacement for restoration backbone research.
Its main value is to show that dirty-lens restoration can be studied not only as a fixed-model restoration problem, but also as a routing problem that decides how much computation each input requires.

\paragraph{Metric trade-offs.}
The balanced mode slightly improves PSNR over Always Base, while SSIM and LPIPS remain comparable rather than uniformly better.
The efficient mode trades a small PSNR loss for a larger latency reduction.
Thus, our claim is a favorable PSNR-latency trade-off, not dominance across every quality metric.
This distinction is important because PSNR measures pixel-level fidelity, whereas perceptual differences may be better reflected by LPIPS and qualitative examples.

\paragraph{Latency estimate.}
The reported latency is a component-based pipeline estimate.
It includes feature extraction, batch router prediction, and selected branch inference, but it is not a fully optimized deployment runtime.
A deployment-oriented implementation should optimize the router or replace it with a lightweight neural module suitable for low-overhead single-image inference.

\paragraph{Router target generation.}
The router is trained using gain targets generated from train\_inner, which is also used to train Tiny and Base.
This does not affect the official validation set, which is held out for final evaluation, but it is not the strictest possible protocol.
A stricter design could use cross-fitting or a separate router-training split so that router targets are generated on restoration-unseen cases.

\paragraph{Branch scope.}
This work uses a simple Input/Tiny/Base branch family.
Stronger backbones or more diverse branches could change the routing behavior and are left for future work.
Overall, the observed branch diversity and PSNR-latency trade-offs suggest that adaptive budget selection complements fixed-model SIDL restoration.
